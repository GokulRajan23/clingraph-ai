ClinGraph AI — Evaluation Plan

Hackathon implementation guide • 12 November 2026, updated 13 November 2026 • Disease-independent

Goal: Demonstrate that users answer patient-history questions faster, with accuracy maintained or improved, and can verify answers against original reports.

1. Prepare the reference answers

Manually label each finding, complication and procedure: assertion (present, absent or uncertain), anatomy, event date, report date, change status, exact evidence sentence and links to related observations across reports. Ideally, have a clinician review the labels. Without clinical review, describe results as prototype testing, not clinical validation.

Keep development, model-selection and final evaluation cases separate. Never select models or tune prompts on the final test set. Split by patient, so the same patient’s reports do not occur in both sets. Define event-matching rules before scoring; do not require identical wording. Count duplicate predictions as errors.

Model-selection benchmark

Before extraction implementation, compare candidate models on identical German clinical examples. Neither a general model nor a medical model is presumed reliable. Use clinician-reviewed labels where available and score abbreviations, negation, uncertainty, historical findings, anatomy, units and temporal comparisons separately.

Record event precision/recall, serious interpretation errors, citation support, handling of insufficient evidence, latency and hardware needs. Record model versions, prompt versions and settings. Check licensing and deployment suitability. Use the model-selection set for this comparison and keep final patient cases unseen. If no candidate performs adequately on the intended task, narrow the task and repeat the benchmark.

Clinical meaning check: A quotation can exist in a report while the generated interpretation is wrong. Evaluate evidence support separately from source-location accuracy. For the MVP, progression labels must be explicitly supported by the report; unsupported interpretation should remain unclear or require review.

Outcome (13 November 2026): DeutschlandGPT with claude-sonnet-5 was selected as the main model for extraction and chat. It was compared with local Qwen 3.5 4B, with identical prompt (v2), schema and scoring. Both reached F1 1.00 on the development set (17 events) and the model-selection set (4 events). Across those 21 events, Claude Sonnet 5 made 3 category errors and no serious errors. Qwen made 10 field errors and 1 negation flip. Claude Sonnet 5 was about 2.2× faster per report. The medically adapted candidate was dropped by team decision. The model-selection set lacks suspected, historical, dated and contradictory cases, so this is a preliminary technical benchmark, not clinical validation. Results and error lists: benchmark/scorecard.md.

Illustrative calculation only: 20 reference events; 18 extracted; 16 correct → precision 16/18 = 88.9%; recall 16/20 = 80%; F1 = 84.2%. These are not ClinGraph results.

3. Use a fixed chatbot question set

Start with approximately 20 questions covering finding lookup, change over time, date comparison, procedures, and missing or conflicting evidence. Write expected answers and supporting passages before running the chatbot.

  • Which complications were documented?
  • How did Finding A change over time?
  • What changed between the first and last reports?
  • When was this procedure documented?
  • Was the condition resolved? Include a case where later reports simply do not mention it.

Score factual correctness, completeness and citation support separately. For unanswerable questions, the correct behavior is to acknowledge insufficient evidence. Not mentioned later does not mean resolved.

4. Compare usefulness with manual review

Compare original reports only with ClinGraph plus access to the originals. Measure answer accuracy and completion time, including source verification. Use different but comparable cases and alternate the condition used first to reduce memory and order effects. Where feasible, add a simple chronological summary as a baseline to test the extra value of linking findings.
